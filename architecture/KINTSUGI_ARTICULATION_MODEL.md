# Kintsugi / Kompendio Articulation Model

This file records the parts of the supplied **Kintsugi_Kompendio** corpus that matter to CivCohe. It is not a claim that every listed integration is implemented.

## Source-derived architecture

The supplied `Konnaxion-kintsugi-and-kompendio-open-source-integration-map-v1.md` describes:

- **Konnaxion** as the existing coordination spine/backbone of the kOA ecosystem;
- a public shell linking education, building and governance into one coherent loop;
- **Kintsugi** as an "open-source under one roof" integration layer;
- shared contracts around identity, permissions, event/audit surfaces and artifact/release packaging;
- **Kompendio** as the reference/integration repertory making dependencies and Mimic-vs-Annex choices explicit.

The ethiKos Kintsugi corpus also emphasizes ownership boundaries, read-only derived readings, canonical objects and adapter-based integration of foreign tools.

## CivCohe interpretation

> **Integrate capabilities without recreating silos and without collapsing all ownership into one undifferentiated monolith.**

\[
Integration \neq Merger
\]

\[
OneCoherentProduct \neq OneMonolithicCodebase
\]

## Mimic

Use a native implementation/pattern when coherent UX, stable canonical ownership, sovereignty, auditability or long-term independence matter.

## Annex

Use an adapter/sidecar when the external tool is mature, replaceability matters, the foreign tool should not own canonical records, or duplication would waste effort.

## Kompendio

Kompendio records dependencies, standards, sidecars, pattern sources, integration contracts and the reasons a capability is Mimicked, Annexed or merely referenced.

## Book relevance

Kintsugi is a concrete architecture for Chapters 4, 8, 17 and 19. It can illustrate interface composition, anti-silo integration, replaceability, bounded ownership, coherent centrality, capability reuse and non-terminal dependency. It must not be used as proof that these goals have been achieved.

# Manuscript Length and Compression Policy

The documentation is intentionally larger than the manuscript.

Do not write the book by expanding every detailed outline bullet. That would create an encyclopedia.

## Working manuscript target

Recommended:
**130,000–160,000 words**, excluding bibliography/index.

This is a planning target, not a theoretical constraint.

## Typical chapter

Usually:
- 4,000–6,500 words.

Foundational chapters may be shorter.
Dense architecture/falsifiability chapters may reach 6,000–8,000 when necessary.

Detailed-outline length does not determine manuscript length.

## Core principle

\[
MasterDocumentation \neq Manuscript
\]

The master documentation preserves:
- alternatives;
- objections;
- local formulas;
- tests;
- implementation notes;
- continuity constraints.

The manuscript selects the subset needed for the reader's argument.

## Preserve

Never compress away:
- central mechanism;
- main distinction;
- strongest counterexample;
- epistemic status;
- main design requirement;
- transition.

## Compress first

1. repeated definitions;
2. long lists of equivalent examples;
3. multiple formulas expressing same relation;
4. repeated cautions that can become one rule;
5. implementation variants better suited to companion volume;
6. edge cases that do not change mechanism.

## One-full-treatment rule

A concept receives one full treatment in its owning chapter.

Later appearances should usually be 1–3 paragraphs unless the concept is transformed at a new level.

## Formula budget

Roughly 8–12 recurrent canonical formulas/relations.

Detailed chapter notations are optional.

## Implementation budget

The flagship should explain enough kOA to:
- make requirements meet implementation;
- expose tradeoffs;
- support falsification;
- show possible instantiation.

It should not become API documentation or exhaustive federation spec.

## Narrative budget

Narrative coherence should appear as a transverse insight, not a second book hidden inside the first.

Surreal/King Klown can be substantial where it illuminates:
- legibility;
- attention;
- cultural contestability;
- founder non-dependence and independent reproduction.

Long artistic exegesis belongs in a companion.

## Series strategy

Keep flagship complete.

Potential companions:
1. **Architectures of Coherence** — detailed institutional/software mechanisms.
2. **Narrative Infrastructures / The Surreal** — fiction as legibility, simulation, memory, attention and cultural precommitment.
3. Applied domain volumes if evidence warrants.

Do not split the flagship's core causal chain across volumes.

## Editing heuristic

Ask:
> If this paragraph disappeared, would the reader still understand why the next mechanism follows?

If yes, move it to documentation or companion material.

## Final standard

The manuscript should feel simpler than the system it describes without becoming simplistic.

\[
RichStructure + SimpleInterface
\]

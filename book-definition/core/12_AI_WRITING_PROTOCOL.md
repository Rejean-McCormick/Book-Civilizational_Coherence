# AI Chapter Writing and Validation Protocol

## Phase 1 — Load context

Load:
1. AI Author Operating Manual.
2. Book Charter.
3. Editorial Contract.
4. Epistemic Protocol.
5. Style Guide.
6. Canonical Formula Register.
7. relevant Part overview.
8. current Chapter Brief.
9. current Detailed Chapter Specification.
10. previous and next Chapter Brief.
11. kOA map if chapter reaches concrete architecture.
12. Narrative Coherence document if chapter is in integration map.

Do not load all detailed chapters unless doing whole-book consistency work.

## Phase 2 — Define proof obligation

Write one sentence each:
- **Question**
- **Claim**
- **Mechanism**
- **Misreading**
- **Design implication**
- **Transition**

If these are unclear, do not draft prose yet.

## Phase 3 — Concept ownership

Make three lists:
- Introduced here
- Reused
- Reserved

Do not steal later chapters' payoff.

## Phase 4 — Evidence map

Mark externally checkable claims:
- SOURCE REQUIRED
- SOURCE OPTIONAL
- CONCEPTUAL
- DESIGN
- IMPLEMENTATION STATE TO VERIFY

Never fill missing empirical support with confident invention.

## Phase 5 — Draft structure

Use 5–8 major movements, not dozens of outline bullets.

Typical:
1. opening phenomenon;
2. distinction/definition;
3. mechanism;
4. dynamics;
5. counterexample;
6. design requirement;
7. concrete architecture;
8. limits/transition.

## Phase 6 — Write theory without kOA

Draft core argument first.

Only once it works, add implementation.

## Phase 7 — Existing approaches

Locate idea in design space:
- standards;
- open source;
- credentials;
- science;
- democratic institutions;
- knowledge graphs;
- version control;
- federalism;
- recommendation systems.

Do not claim novelty merely because combination is distinctive.

## Phase 8 — Add kOA

Use:
- function first;
- name second;
- intended vs verified state clearly distinguished;
- no exclusivity claim.

Ask:
> What contradiction does this mechanism expose that abstract theory could avoid?

If none, kOA passage may be unnecessary.

## Phase 9 — Counterexample/failure

At least one serious counterexample should threaten the attractive principle.

Then:
- concede;
- narrow;
- derive safeguard;
- identify empirical remainder.

## Phase 10 — Formula audit

For every displayed formula:
- literal translation?
- meaning?
- status?
- needed?
- canonical notation?

Delete decorative formulas.

## Phase 11 — Narrative audit

Where narrative appears:
- fiction clearly contextualized?
- points back to inspectable mechanism?
- argument survives without King Klown?
- narrative being used as evidence? If yes, rewrite.
- narrative supports critique rather than loyalty?

## Phase 12 — Continuity audit

Check:
- previous premise;
- current new contribution;
- next unanswered question.

## Phase 13 — Repetition audit

Search for:
- repeated definitions;
- long "as we saw" passages;
- duplicate lists;
- repeated caveats.

Keep spiral, remove duplication.

## Phase 14 — Prose audit

Replace outline fragments and nested labels with cohesive prose.

Keep lists only where list is itself concept.

## Phase 15 — kOA removal test

Mentally delete implementation section.

If chapter collapses, theory is underdeveloped.

## Phase 16 — final questions

1. Can skeptic state claim fairly?
2. Normative vs functional separated?
3. Uncertainty visible?
4. One memorable distinction?
5. Main example explanatory?
6. Implementation scoped?
7. Real failure condition?
8. Next chapter necessary?

# Chapter 21 Brief — Determinism, Offline Operation and Optional AI

**Status:** normalized V2 chapter contract. Higher authority than the detailed chapter specification for scope, canonical distinctions and claim status.

## Entry state
Part V has established local boundaries and optional federation.

## Proof obligation
Separate AI-assisted construction from AI-dependent operation and make deterministic/offline continuity a sovereignty property where feasible.

## Main mechanism
Canonical functions use explicit inputs, rules and versions; network and AI add optional capabilities rather than hidden core dependencies.

## Canonical distinctions to protect
- Built With AI ≠ Powered By AI
- Determinism ≠ Correctness
- AI Output ≠ Canonical State
- Offline ≠ Isolated Forever
- Architectural Capability ≠ Validated Readiness

## Best worked example
Local instance continues relevant core operations with internet=0 and AI=0, then later imports updates.

## Serious counterexample / failure pressure
Deterministic systems can reproduce errors; some tasks intrinsically require current network data; offline promises must be tested.

## kOA role

## Epistemic status

## Reserved concepts / do not pre-solve

## Exit condition

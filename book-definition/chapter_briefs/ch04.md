# Chapter 4 Brief — Interfaces Matter More Than Nodes

**Status:** normalized V2 chapter contract. Higher authority than the detailed chapter specification for scope, canonical distinctions and claim status.

## Entry state
Chapter 3 located losses at transitions.

## Proof obligation
Show that when competent nodes already exist, interface quality can dominate system performance.

## Main mechanism
Interfaces provide discovery, translation, qualification, coordination, feedback and memory. A strong articulation hub can function as an interface-of-interfaces, compressing many specialized capabilities into one coherent surface. The kOA laboratory also seeks common primitives across domains, but shared core must not erase domain-specific constraints. Couplings are directional, selective and power-laden.

## Canonical distinctions to protect
- Connection ≠ Interface
- Interoperability ≠ Uniformity
- Composition ≠ Absorption
- More Interfaces ≠ More Coherence
- Component Understanding ≠ System Understanding
- One Coherent Surface ≠ One Monolithic Codebase
- Functional Centrality ≠ Sovereignty

## Best worked example
Two high-quality institutions with incompatible terminology, authority and handoff procedures.

## Serious counterexample / failure pressure
Sometimes the node really is the bottleneck. The title is a conditional claim, not universal law.

## kOA role
Concrete interface examples only after deriving functions. Narrative mediation can appear as an interface of totality.

## Epistemic status
Interface priority is a conditional systems hypothesis.

## Reserved concepts / do not pre-solve
Why bad interfaces persist and the power they generate.

## Exit condition
If interfaces can be redesigned, why do inefficient arrangements reproduce themselves?

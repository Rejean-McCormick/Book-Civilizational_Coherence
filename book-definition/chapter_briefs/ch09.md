# Chapter 9 Brief — From Information to Cumulative Knowledge

**Status:** normalized V2 chapter contract. Higher authority than the detailed chapter specification for scope, canonical distinctions and claim status.

## Entry state
Power and accountability depend on memory.

## Proof obligation
Show that experience, storage and activity do not automatically become cumulative knowledge.

## Main mechanism
Experience must be captured, interpreted, codified, transmitted and reused. Memory is what can be reactivated to improve future action.

## Canonical distinctions to protect
- Experience ≠ Learning
- Storage ≠ Memory
- Decision Memory ≠ Deliberation Memory
- Deprecation ≠ Deletion
- Cumulative Knowledge ≠ Single Canon
- Documentary Memory ≠ Narrative Memory

## Best worked example
A team solves a recurring problem, stores files, loses people and later rediscovers the solution from scratch.

## Serious counterexample / failure pressure
More memory can ossify institutions; forgetting and deprecation can be useful.

## kOA role
Kristal as later portable artifact; decision/outcome histories. Narrative memory retains warnings but points back to auditable records.

## Epistemic status
Cumulative-memory chain is conceptual; reuse needs empirical measures.

## Reserved concepts / do not pre-solve
Portability, epistemic pluralism and semantic structure.

## Exit condition
If memory is trapped in one platform, how cumulative is it really?
